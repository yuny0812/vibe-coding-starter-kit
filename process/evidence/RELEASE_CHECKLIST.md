## 프로젝트 시작 전 사용자가 답해야 할 질문

- 어떤 환경을 릴리스 후보로 검증하는가? `[답변]`
- 릴리스 승인자는 누구인가? `[답변]`
- `미확인` 상태를 예외 승인할 수 있는 조건과 사람은 누구인가? `[답변]`
- 배포 실패를 누가 어떤 채널로 알게 되는가? `[답변]`
- 롤백 목표 시간과 담당자는 누구인가? `[답변]`

## 명세 정합성

- [ ] 모든 요구사항 ID와 acceptance criteria에 검증 증거가 있다.
- [ ] 코드와 명세의 드리프트가 없거나 문서를 갱신했다.
- [ ] Out of Scope가 의도치 않게 구현되지 않았다.

## 동작과 사용자 경험

- [ ] 핵심 정상 흐름을 실제 환경에서 실행했다.
- [ ] 주요 예외·오류 흐름을 실제로 발생시켜 확인했다.
- [ ] 빈 상태, 최소 데이터, 예상 최대 규모를 확인했다.
- [ ] 역할별 인증·권한 동작을 확인했다.
- [ ] 중복 요청·재시도·새로고침 시 동작을 확인했다.

## 데이터와 계약

- [ ] API·schema·공통 타입의 호환성을 확인했다.
- [ ] migration을 빈 DB와 기존 데이터가 있는 DB에서 확인했다.
- [ ] rollback 또는 복구 절차를 실제로 확인했다.
- [ ] 시간대, 단위, 소수점, 보존·삭제 규칙을 확인했다.

## 품질과 보안

- [ ] lint, typecheck, test, build 등 필수 명령이 통과했다.
- [ ] 심각한 코드 리뷰·보안 리뷰 지적이 남아 있지 않다.
- [ ] 비밀값·개인정보가 코드, 로그, 오류 메시지, evidence에 없다.
- [ ] 새 의존성의 필요성, 유지보수성, 라이선스를 확인했다.

## 운영과 인계

- [ ] 로그·지표·알림으로 실패를 감지할 수 있다.
- [ ] 배포와 롤백 절차, 담당자, 접근 권한이 확인됐다.
- [ ] 정기 작업과 수동 운영 작업에 주체와 주기가 있다.
- [ ] runbook 또는 handoff가 현재 구현과 일치한다.
