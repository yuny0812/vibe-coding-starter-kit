# Project Conventions

- 문서 상태: `DRAFT | REVIEW | APPROVED`
- 최종 수정일: `YYYY-MM-DD`

이 문서는 사람과 에이전트가 동일한 방식으로 저장소를 설치, 실행, 변경, 검증하기 위한 실무 규칙입니다. 실제로 실행 가능한 명령만 적습니다.

## Repository Layout

| 경로 | 책임 | 두면 안 되는 것 |
|---|---|---|
| `src/` | 제품 코드 | 생성물, 비밀값 |
| `apps/frontend/` | 웹·앱 UI와 프론트엔드 테스트 | 서버 비밀값, 백엔드 도메인 로직 |
| `apps/backend/` | API·작업 처리·백엔드 테스트 | 프론트 UI, 클라이언트 전용 상태 |
| `packages/contracts/` | OpenAPI, 이벤트, 공유 스키마 | 제품 로직 |
| `packages/shared/` | 양쪽에서 재사용 가능한 최소 공통 코드 | 서비스별 구현 세부사항 |
| `database/` | 마이그레이션, seed, 데이터 규칙 | 런타임 비밀값 |
| `infra/` | 로컬·배포·관측성 인프라 정의 | 애플리케이션 도메인 로직 |
| `process/context/` | 현재 코드베이스의 탐색 가능한 지식 | 제품 요구사항 원문 |
| `process/plans/` | 활성·보류·완료 작업 기록 | 장기 아키텍처 결정 |
| `process/evidence/` | 테스트·리뷰·수동 검증 증거 | 실제 비밀값·운영 개인정보 |
| `skills/` | 프로젝트 전용 반복 작업 레시피 | 프로젝트 사실의 중복 |
| `tools/` | 프로젝트 전용 개발·운영 도구 | 앱의 비즈니스 로직 |
| `src/` | 단일 서비스 프로필의 제품 코드 | 풀스택 앱 코드와의 중복 |
| `tests/` | 서비스 간 통합·계약·E2E 테스트 | 앱 내부 단위 테스트, 운영 비밀값 |
| `scripts/` | 반복 가능한 개발·운영 보조 작업 | 개인 전용 임시 스크립트 |
| `docs/` | 프로젝트 Source of Truth | 빌드 생성물 |

## Environment & Secrets

- 공개 가능한 키 이름과 예시는 `.env.example`에만 둡니다.
- 실제 값은 `[비밀 관리 도구/로컬 방법]`에 저장합니다.
- 환경변수 이름 규칙: `[UPPER_SNAKE_CASE 등]`
- 새 환경변수 추가 시 갱신할 곳: `[.env.example, 배포 설정, 문서 등]`
- 로그 금지 데이터: `[토큰, 비밀번호, 개인정보 등]`
- 테스트용 비밀값 정책: `[답변]`

## Dependency Policy

새 의존성 추가 전 다음을 확인합니다.

- [ ] 표준 라이브러리나 기존 의존성으로 해결할 수 없는가?
- [ ] 라이선스와 유지보수 상태가 허용 가능한가?
- [ ] 보안 취약점과 공급망 위험을 확인했는가?
- [ ] 번들 크기, 성능, 운영 복잡성 영향을 확인했는가?
- [ ] 제거 또는 대체가 쉬운 경계로 도입했는가?
- [ ] `[승인권자/조건]`의 승인이 필요한가?
