# Acceptance Criteria

- 문서 상태: `DRAFT | REVIEW | APPROVED`
- 최종 수정일: `YYYY-MM-DD`
- 승인자: `[답변]`

이 문서는 "언제 끝났다고 말할 수 있는가"를 정의합니다. 각 criteria는 관찰 가능하고 재현 가능해야 합니다.

## 프로젝트 시작 전 사용자가 답해야 할 질문

1. 핵심 사용자 흐름별로 성공한 상태를 눈으로 확인할 수 있게 설명하면 무엇인가?
   - `[답변]`
2. 입력의 정상값, 경계값, 잘못된 값에서 각각 어떤 결과가 나와야 하는가?
   - `[답변]`
3. 오류, 외부 서비스 장애, 권한 부족, 네트워크 단절 시 기대 동작은 무엇인가?
   - `[답변]`
4. 각 비기능 요구사항을 어떤 도구와 수치로 검증할 것인가?
   - `[답변]`
5. 어떤 테스트가 자동화되어야 하고 어떤 항목은 수동 확인이 필요한가?
   - `[답변]`
6. 지원할 환경, 브라우저, 기기, 데이터 조건은 무엇인가?
   - `[답변]`
7. 회귀가 절대 허용되지 않는 기존 동작은 무엇인가?
   - `[답변]`
8. 누가 최종 결과를 승인하며 어떤 증거가 필요한가?
   - `[답변]`

## 작성 규칙

- ID는 `AC-001`, 비기능 criteria는 `AC-NF-001` 형식을 사용합니다.
- Given/When/Then 하나에는 하나의 동작만 검증합니다.
- "정상 동작한다" 대신 입력, 행동, 관찰 결과를 적습니다.
- 가능한 경우 요구사항 ID, 테스트 경로, 증거를 연결합니다.

## Feature Acceptance Criteria

### AC-001 — `[사용자 결과 이름]`

- 관련 요구사항: `FR-001`
- 우선순위: `MUST`
- 검증 방식: `자동 | 수동 | 혼합`

```gherkin
Given [초기 상태와 전제 조건]
When [사용자가 수행하는 단일 행동]
Then [관찰 가능한 결과]
And [필요한 추가 결과]
```

예외/경계 조건:

- Given `[경계 또는 오류 조건]`, When `[행동]`, Then `[안전하고 명확한 결과]`.

증거:

- 테스트: `[tests/... 또는 TBD]`
- 스크린샷/로그/리포트: `[위치 또는 해당 없음]`

### AC-002 — `[다음 사용자 결과]`

- 관련 요구사항: `FR-002`
- 우선순위: `SHOULD`
- 검증 방식: `자동 | 수동 | 혼합`

```gherkin
Given [전제 조건]
When [행동]
Then [결과]
```

## Definition of Done

- [ ] 모든 `MUST` 요구사항이 대응하는 acceptance criteria를 통과했다.
- [ ] 필수 품질 gate가 통과했다.
- [ ] 새 동작과 회귀 위험을 다루는 테스트가 있다.
- [ ] 환경변수, API, 사용자 흐름, 운영 방식 변경이 문서에 반영됐다.
- [ ] 비밀정보, 디버그 출력, 불필요한 생성물이 없다.
- [ ] 마이그레이션과 롤백이 필요한 경우 검증됐다.
- [ ] 미검증 항목과 잔여 위험이 명시됐다.
- [ ] 지정된 승인자가 결과를 승인했다.
